Espace Pédagogique - Matrix Scanner

Cet outil a été conçu dans un but éducatif pour comprendre l'enchaînement des outils lors d'un test d'intrusion. Voici les deux chaînes de traitement automatisées (Workflows) disponibles.

Workflow : Scanner Distant (Aiguillage Intelligent "Smart Branching")

Cible Web
Domaine (WHOIS, Subfinder, Sublist3r, theHarvester & DNS Probe)
Détection WAF (Wafw00f)
Capture (Gowitness)
Empreinte (WhatWeb)
Nmap
CVE
Audits (CMS ↔️ Nuclei, Gobuster, ParamSpider ➡️ SQLMap)

Workflow externe automatisé avec Aiguillage Intelligent (Outils Kali) : Interroge le WHOIS et énumère les sous-domaines (Subfinder/Sublist3r/theHarvester/DNS Probe), détecte le WAF (Wafw00f), capture le site (Gowitness), analyse l'empreinte (WhatWeb), cartographie les ports (Nmap), recherche les vulnérabilités (CVE) puis déclenche dynamiquement les scanners dédiés avec le Smart Branching : Si un CMS est détecté, son scanner spécifique est lancé (WPScan, Joomscan...). Si la cible est "Custom" (sans CMS), l'outil lance Nuclei pour tester des modèles de failles 0-days. En parallèle, on lance le Fuzzing d'arborescence (Gobuster), et pour les Bases de données (ParamSpider extrait d'abord toutes les anciennes URLs vulnérables depuis les Web Archives, puis les transmet en masse à SQLMap/NoSQLMap pour maximiser les chances d'injection).

Workflow : Scanner Local (Intranet & LAN)

Cible LAN
Découverte ARP (Netdiscover)
Identité & NetBIOS (mDNS & nbtscan)
Ports & OS (Nmap)
Énumération SMB (Enum4linux, SMBMap)
CVE & Exploits (Exploit-DB)

Workflow interne automatisé : Cartographie les équipements (IP/MAC) via ARP (Netdiscover), identifie la marque/catégorie via NetBIOS/mDNS, sonde les ports et OS (Nmap), énumère les partages Windows/Samba (Enum4linux, SMBMap) et croise les bannières avec la base d'exploits (Searchsploit/CVE).

Résilience Réseau & Rotation d'IP (Proxychains & Tor)

Backend Flask
Détection Automatique du Port SOCKS Tor (9050)
Injection de Proxychains
Commande Tor NEWNYM (Port 9051)

Le système intègre une **résilience réseau** robuste : Dès que le daemon Tor (OnionHop) est allumé, le backend détecte l'ouverture du port `9050` et injecte dynamiquement `proxychains4` devant toutes les requêtes (Nmap, SQLMap, Nuclei...). Si votre IP publique est bannie (403, WAF), un simple clic sur le bouton **Changer d'IP** envoie la commande `SIGNAL NEWNYM` au port de contrôle `9051` de Tor pour forcer la création d'un nouveau circuit et vous attribuer instantanément une nouvelle identité IP sur le web.
